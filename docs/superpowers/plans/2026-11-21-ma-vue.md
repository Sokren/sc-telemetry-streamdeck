# « Ma vue » Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Onglet « Ma vue » de l'appli web : sections et cases composées par l'utilisateur, glisser-déposer, cadenas, vue enregistrée dans l'appli.

**Architecture:** Le serveur valide et enregistre la disposition (`view.json`) et la diffuse (route + événement SSE `view`). La page rend les cases à partir du flux `state` existant et gère l'édition (événements pointer).

**Tech Stack:** TypeScript (Node ≥ 24, node:http), vitest, page en JS module sans bibliothèque.

**Spec:** `docs/superpowers/specs/2026-11-21-ma-vue-design.md`

## Global Constraints

- Plugin Stream Deck et onglet Grille inchangés ; `npm test`, `npm run build`, `npm run build:web`, `streamdeck validate com.sokren.sc-telemetry.sdPlugin` verts.
- Tout texte visible FR + EN (`i18n.js`), descriptions OpenAPI avec « — FR : ».
- **Aucun commit** : Remi teste avant (demande explicite). Branche `feat/ma-vue`.
- Limites : 20 sections, 40 cases / section, titre ≤ 40 car., ids `^[A-Za-z0-9_-]{1,32}$`, action `^[a-z0-9_]{1,64}$` hors `DANGEROUS_ACTIONS`.
- Contrat OpenAPI → `1.2.0`.

## Review Focus

- `view.json` corrompu ou d'un autre format → vue par défaut + `view.json.bak` (test dans Task 1).
- PUT avec action dangereuse (`v_self_destruct`) → 400 `invalid_view`, fichier inchangé (Task 2).
- PUT avec ids en double ou titre de 200 caractères → 400 / titre tronqué ? → **400** pour ids en double, titre **tronqué** à 40 (Task 1).
- Deux pages ouvertes : un PUT sur l'une pousse `view` à l'autre (Task 2, test SSE).
- Corps > 64 Ko déjà refusé par `http.ts` (400) — rien à ajouter.

### Task 1: Modèle et stockage de la vue

**Files:**
- Create: `src/web/view.ts`
- Test: `tests/web/view.test.ts`

**Interfaces:**
- Produces:
  - `type ViewItem = { id: string; kind: ItemKind; ref?: string; size: 1 | 2 }`
  - `type ViewSection = { id: string; title: string; width: "half" | "full"; items: ViewItem[] }`
  - `type View = { version: 1; sections: ViewSection[] }`
  - `ITEM_KINDS = ["vital","instrument","annunciators","ship_info","character_info","ship_function","action"]`
  - `DEFAULT_VIEW: View` (Survie / Vol / Commandes du vaisseau, cf. spec)
  - `parseView(x: unknown): View | undefined` — normalise (titre tronqué à 40, vide → "Section"), `undefined` si invalide.
  - `class ViewStore { constructor(file?: string); get(): View; set(v: View): void; onChange(fn: (v: View) => void): () => void }` — sans fichier : en mémoire.

- [ ] Tests : `DEFAULT_VIEW` passe `parseView` ; refus : kind inconnu, `vital` ref inconnue, action dangereuse, ids en double (sections ou cases), 21 sections, 41 cases, size 3 ; titre 200 car. → 40 ; titre vide → "Section" ; `ViewStore` sans fichier → défaut ; `set` puis nouveau `ViewStore(file)` relit ; fichier invalide → défaut + `.bak` ; `onChange` appelé sur `set`.
- [ ] Lancer `npx vitest run tests/web/view.test.ts` → échec.
